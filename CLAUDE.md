# CLAUDE.md — The Power Hour

Context for Claude Code working in this repo. Read README.md for the user-facing overview.

## What this is

A shareable website for Dan's 12-team Sleeper fantasy league, **NFL Fantasy Championship** (league ID `1312001652454088704`, 2026 season). Leaguemates open it to see power rankings with explanations, a live waiver/trade feed, weekly matchup odds, and "nerd lab" stats. "The Power Hour" is also the name of Dan's league newsletter. Hosted on Vercel from GitHub; every push to the main branch deploys.

League facts the code relies on: half-PPR, 12 teams, starting slots QB, RB, RB, WR, WR, TE, FLEX, FLEX, K, DEF + 5 bench. Regular season ends week 14, playoffs start week 15, top 6 make it. Standings tiebreaker is points for. Waivers are rolling (no FAAB used in practice).

## Architecture

No framework, no build step, no npm dependencies. Plain ES modules served as static files.

- `index.html`, `styles.css`, `app.js` — the site. The browser never calls the Sleeper API: it loads `/api/league?d=KEY` and `/api/ros?d=KEY`, where KEY is the Central date rolling over at 6am (`morningKey()`), so each is fetched once per morning and shared from the CDN.
- `api/league.js` — the morning Sleeper snapshot: state, league, users, rosters, matchups weeks 1–14, transactions weeks 1–current, plus `fetched`. It only answers the current key from `leagueKey()` (any other `?d=` gets a 307 to it) and keeps each snapshot in the store (`once('league', key)`, 3 days), so a deploy (Vercel empties the CDN) never re-reads Sleeper. `X-Snapshot` says `store` or `live`. `s-maxage=86400`; errors are `no-store`. Also exports `snapshot()` for scripts. Hash routing: `#live` (only during a live week), `#rankings`, `#wire`, `#matchups`, `#trades`, `#lab`.
- `api/ros.js` — Vercel serverless function (Node 18+, global `fetch`). Scrapes the three ROS sources, fetches Sleeper's `/players/nfl` (~5 MB), matches players to Sleeper IDs, returns `{ updated, sources, weights, players: {id: {n,p,t,i,a}}, values: {id: {v, r, spread, pos, wk, fl, cl, ir, sos, g, rk, prk, wkEst?}}, byes: {TEAM: week} }`. Bye weeks come from FantasyPros (`player_bye_week` on every ecrData row). Only the current `morningKey()` is served (others redirect). Sleeper's player map is slimmed to fantasy positions and stored on its own (`once('players', key)`), so it's read at most once per morning; the built body is stored for 3 days, or 1h when a ranking source failed (the retry re-scrapes the rankings and reuses the stored players). Edge-cached 24h (`s-maxage=86400`), 1h if a source failed. No cron; the only database is the fan-picks store behind `api/votes.js`.
- `lib/newsclock.js` — the shared clock (page and API): `TZ`, `NEWS_CLOCK` (hold, late pull, night edition, game window), `morningKey`, `leagueKey`, `isOnHold`, `isNightDesk`, `inGameWindow`. Export names must not clash with names in `app.js`: the preview bundler flattens modules into one scope and can't follow `import { a as b }`.
- `lib/snapstore.js` — `once(name, key, produce)`: each snapshot kept gzipped in the Upstash store (same env vars as the fan picks) under its clock key, with a lock so simultaneous first visitors share one pull. Without the env vars it falls back to pulling on each CDN miss. `scripts/test-snapshots.mjs` counts Sleeper calls.
- `lib/sources.js` — regex-only parsers (must run in Node without a DOM):
  - FantasyPros: `var ecrData = {...};` embedded in the page HTML (~400 players incl. K/DST).
  - DraftSharks: the page only server-renders 25 rows; the full list is `GET /ros-rankings/load-rows?offset=0&limit=600&...` (HTML `<tr class="player-row">` fragments, includes IDP, re-ranked within offense). Also provides weekly proj pts, floor, ceiling, injury risk %, SOS, projected games.
  - LeagueLogs: server-rendered `<table>`, 200 players incl. DST, no K. Its order nearly mirrors FantasyPros ECR, so it is weighted 0.5.
- `lib/consensus.js` — `normName` + `NICKNAMES` map, `buildIndex(sleeperPlayers)`, `matchRow`, `buildConsensus`. Rank → value is `100 * exp(-0.0115 * (rank-1))`, weighted average across sources (`SOURCE_WEIGHTS`). Missing weekly projections are filled by a per-position linear fit of DraftSharks pts vs value, falling back to `DEFAULT_FIT` if DraftSharks is down.
- `lib/engine.js` — `computeLeague(input)`: pure, no DOM, runs in browser and Node. Produces teams (sorted by power rank), weekly results, all-play, luck, efficiency, ROS best lineup (greedy fixed-then-flex), position-group ranks, power score + rank history, Monte Carlo playoff odds and championship odds (10k sims, seeded; the playoff bracket is simulated on Sleeper's fixed 4/6/8-team bracket, giving `champPct`/`finalPct`), matchup previews, explanations (`explain`), tiers (`tierFor`), transaction feed with ROS value deltas (trades priced over replacement: each net extra player received costs `meta.replacement`, the mean value of the top 3 free agents, so consolidation trades are not penalised; waiver moves stay raw), best available free agents, "divisive" players.
- `lib/stories.js` — the newsroom, pure like the engine. `buildStories(D, {now, dateKey})` scores candidate stories (fresh trades and wire moves, unbeaten/winless/streaks, last week's upsets/blowouts/nail-biters, rank moves, luck, game of the week) and returns `{lead, more}`; a date-seeded jitter rotates near-ties daily. `keyMatchup(D)` picks the game of the week by 0.55 × stakes + 0.45 × closeness, where stakes is the combined playoff-odds swing (`playoffIfWin − playoffIfLoss` from the simulation). `matchupQuips(D)` gives one data-driven one-liner per matchup, no repeated joke within a week.
- `api/votes.js` — fan picks. GET `?week=&voter=` returns `{week, open, counts: {"3-8": {"3": n}}, mine}`; POST `{week, pair, pick, voter}` records a vote (re-voting replaces the device's pick). Storage is Upstash Redis over its REST pipeline API with plain fetch (env `KV_REST_API_URL`/`KV_REST_API_TOKEN` or `UPSTASH_REDIS_REST_*`); without them GET returns `{enabled: false}` (200, no console noise), POST returns 503, and the UI hides voting. Server validates against the cached `/api/league` snapshot on its own host (current week, real pair, pick in pair), never Sleeper directly, and closes voting from Thursday 7:15pm Central through Monday or once the snapshot shows points. `VOTES_NOW` env overrides the clock in tests. Soft cap of 3 voters per hashed IP per matchup. Keys `ph:votes:{week}:{pair}` (hash voter→pick) and `ph:net:{week}:{pair}:{iphash}` (set), 120-day TTL. The client keeps its voter id in `localStorage` `ph-voter` and hides the split until you've voted.
- `lib/matchup.js` — `breakdown(D, preview)`: this week's lineups slot by slot (the starters set in Sleeper, from `preview.startersA/B`; best projected lineup when a team hasn't set one), position-group edges, and up to 6 prioritised "things to watch" (starters ruled out or on a bye, legal lineup swaps found by greedy slot-eligible bench swaps, doubtful/questionable starters, biggest edges, close or lopsided totals, the widest floor-ceiling swing player, QB stacks, shared NFL offenses, hot or cold form). The engine's `thisWeekProj` is zero for players ruled out or on a bye (`byes` input), which also feeds this week's win odds. `helpers.player(id)` returns name, NFL team, status, bye, proj, floor, ceiling.
- `lib/trades.js` — `tradeIdeas(D, rid)`: brute-force search of every 1-for-1, 2-for-1 and 1-for-2 swap with each other team (skill positions, value >= 8; about 50ms). Kept only if the requester's best ROS lineup gains >= 0.3 pts/wk, the partner's doesn't drop and gains >= 0.1 unless they win the value side by >= 3, and value (over replacement, same rule as the trade ledger) is within max(6, 15% of the deal). Roster fallout is modelled: an extra player received forces the lowest-value skill player to be cut; a freed spot adds the best free agent. Max 2 ideas per partner and per incoming headliner. Explanations come from position-group ranks before and after. No AI model involved; it is a deterministic search.
- `lib/members.js` — `MEMBERS`: Sleeper user_id → `{first, photo}` for the league managers, with headshots in `assets/heads/<photo>.jpg` (320px square JPEGs cropped from the originals, about 25 KB each). `photoUrl()` reads `window.__HEADS__` first, which `bundle-preview.mjs` fills with data URIs. In `app.js`, `avatar(t)` stays the Sleeper team picture (Dan wants team pictures in the ranking rows, the wire and the matchup cards); `headshot(t, cls)` is the manager photo (falls back to `avatar`). Headshots appear in the headline photos (`leadFaces`, with a `STAMPS` label per story type), the manager card at the top of an opened ranking row (`managerCard`, plus `superlatives` badges), the game of the week poster (`faceoff`) and its playoff-drive legend, the busiest manager in the wire stat strip, who shook on each trade card (`dealFaces`), the partner on your best Trade Lab idea (`.pitch`), photo marks in the scatter chart and on your own line in the bump chart (`img`, `faceDot` in charts.js), your face next to the team picker (`paintMe`), and the editor line in the footer. Last place (the "This Guy Stinks" tier) gets the `.drained` grayscale. Keep them sprinkled: one or two personal moments per page, not every list. A new manager needs an entry in `MEMBERS` and a cropped photo.
- `lib/bullseye.js` — money week side pots. `bullseye(D, {week, target})`: during the week, every team's projection (banked plus the rest, same as the previews) sorted by distance from the target, plus `pWin` from 20k seeded draws of who lands closest; the week after, the final scores and the winner; `soon` before; null otherwise. `MONEY_WEEK` in `app.js` (week, target, prize, usual, title, honoree, flyer) drives a lead headline (`moneyStory`, always first while it runs), the bullseye board on the matchups page (`bullBoard`: rules, the $40 → $80 ticket, the flyer at `assets/money-week-flyer.jpg`, a target chart `bullTarget` on a square-root scale with the closest three as faces, and the full table) and a distance chip on each matchup card (`bullTag`). Set `MONEY_WEEK` to the next one, or null.
- Defending champion: `CHAMPION` in `app.js` (Sleeper user_id, season). `champTag`/`champBadge` put the `TROPHY` svg by their team name (ranking row, futures, headline rows, matchup cards, bullseye table), on their photo (headline, manager card, face-off, footer), and add a "Defending champion" badge to the manager card. Update it after each title.
- Matchup cards stay light: one moneyline row (`.ml`) under the win bar; `betLine` puts the rest of the book behind a "More odds" toggle (`.odds-open` on the card): spread, total, team totals, nail-biter (margin under 5) and blowout (20+) props from the same normal margin model as the win odds (`phi`), money week closest-to-target odds, and the playoff stakes line. The open selector is scoped (`.mu.open .mu-detail`) so the lineup breakdown and the odds open separately.
- The news clock: `NEWS_CLOCK` in `app.js`, in Central minutes from Sunday midnight (`weekMinute`). Sunday noon to 10:45pm (`onHold`) the headline card carries a yellow "Games in progress" strip (`.desk-note`). At 10:45pm (`late`) `leagueKey()` switches the league snapshot to `<morning key>-late`, a fresh CDN cache key, so the first visitor after Sunday night football triggers one new Sleeper pull (`/api/ros` keeps the morning key). From then until Tuesday 6am (`nightDesk`) the headlines are the night edition. `?at=<ISO time>` fakes the clock for testing. A single Sunday's late pull can be moved with `LATE_OVERRIDES` in `lib/newsclock.js` (that Sunday's Central date → minutes after midnight); the hold banner ends and the night edition starts at the moved time, and the late key covers the rest of the night, so there is no second pull.
- The final call (Monday night): at 10:45pm Monday (`NEWS_CLOCK.final`, movable per Monday with `FINAL_OVERRIDES` in `lib/newsclock.js`) `leagueKey()` switches to `<morning key>-final`, one more Sleeper pull (approved by Dan) that carries Monday night's scores. Whenever the snapshot shows every game of the week final (`nightBoard` shows nobody left; data only, no clock), `DATA.finalCall` is set and `load()` runs `buildFinal()` straight away, so every device shows the same new rankings: headlines come down, the Live tab reads "Final" and becomes Final Scores (final week list, standings after the week), and a centred button ("Done with Live Ranks, Show me the Power Ranking", `revealCta`) opens an optional overlay (`openReveal`, `.unveil`; not `.reveal`, which is the scroll animation's class): pick your team, get the verdict on your week (`verdict`: congratulations or a roast by margin, weekly rank, standings move, money week winner), then after a 6 s bar the page lands on the power rankings, already computed from `asFinal(RAW, 'now')` (this week's scores counted into records and points for). Sleeper's own scoring isn't needed. A one-off second pull for a Monday whose 10:45pm pull went out too early: `FINAL_REPULL` in `lib/newsclock.js` (Monday's date → minutes after midnight) switches the key to `<morning key>-final2` from then until Tuesday 6am (used Oct 26, week 7). The final-scores page stays reachable afterwards (`DATA.after`, rendered through `withData`). Test with a played-week demo and `?at=`.
- The important message (`MESSAGE_VIDEO` in `app.js`, `assets/important-message.mp4`; set null to drop it): the first time a device sees the real power rankings (not the on-hold page), `maybeMessage` takes over the screen ("Important Message Incoming", "Please watch.", 3-2-1) and plays the video with sound, falling back to a "Tap to play" button when the browser blocks sound (phones). Skip appears 5 s in; seen once it ends or is skipped (`localStorage` `ph-video-<id>`). A "Watch the important message again" chip in the rankings head replays it. Nothing shows until a HEAD request finds the file, and never in the preview bundle. Playwright's bundled Chromium can't play H.264, so test it in real Chrome (`channel: 'chrome'`) or WebKit.
- The week 7 shakeup (`SHAKEUP` in `app.js`; null drops it): while week 7 is the last scored week and no week is live (after the reveal, or once Sleeper scores it), the rankings carousel is `shakeupStories()`: the shakeup lead (moves against week 6 ranks on `OLD_WEIGHTS`, the formula people saw before; the deck spells out the new formula's shares), `closeGames()` (the two closest finishes from `matchups[7]`, plus the loser's biggest same-position bench regret if it beats the margin), then the money week result. Above the ranks sits the fan poll (`pollCard`, `#poll-slot`): the bottom six of the new ranks. `api/poll.js` allows one vote per device and no changing it (409 for a second try). A device is a random id the server hands out, kept in an HttpOnly cookie (`ph_dev`) and in `localStorage` `ph-device` (sent with each call), so clearing one doesn't make a new voter. A vote under either id counts as voted (`SET NX` on `ph:poll:{id}:dev:{id}`), and each hashed IP is capped at `MAX_PER_NETWORK` (4) devices per poll against private-window ballot stuffing. The first vote freezes the six choices (`ph:poll:{id}:options`) so the morning refresh can't reshuffle them, and only ids in its `POLLS` are accepted. `scripts/test-poll.mjs` covers it.
- `lib/nightdesk.js` — the night edition, pure. `nightBoard(D)` splits this week's games, using the breakdown's set lineups, into locked (the trailing side's Monday players can't cover the gap even at their DraftSharks ceilings, or nobody is left, or the leader is above 98.5%) and Monday-decides. `nightEdition(D, {dateKey, editor, people})` writes three aggressive headlines (the tightest Monday decider, the biggest locked game, then the next best; the editor's own live game is always in), with first names from `people` and decks carrying scores, the Monday players and projections, win odds, the new records or the playoff-odds swing. It returns null unless at most four NFL teams are still to play, so a mid-Sunday snapshot never gets a night edition. Money week still leads, so the carousel shows four slides that night.
- Live-week mode (`DATA.liveMode`): during the game window (`gameWindow()`, Thursday 7:15pm to Tuesday 6am Central) or whenever this week has points (`DATA.live`), as long as the week is unscored, the Live tab (`viewLive`, `#live`, hidden otherwise) is the front page and the brand link. It carries the headline carousel, weekly rankings 1–12 by projected final (`liveWeek()`: banked plus the rest projected, the previews' numbers; banked vs still-to-come bar; status chip from `nightBoard`: won, locked, can't catch, or win %) and projected standings (each game goes to the side more likely to win, projected score added to points for, the tiebreaker; seed change vs now, the playoff cut line, season playoff odds). The power rankings tab stays reachable but shows "On hold" and a notice that they update Tuesday morning, with no carousel. Phones show short tab labels (`.tl`/`.ts` spans: Live, Power, Wire, Games, Trades, Lab). The bare URL opens Live; an explicit hash still wins. The weekly list and the standings sit side by side from 1100px (`.live-grid`, standings sticky, PF column moved into the After tooltip), stacked below. Above them, `yourWeek()` is the desk's note to whoever picked a team (headshot, rotating line by situation: won/locked, comfortable, losing, close and ahead gets hype, close and behind gets a reality check; extra jab for last place), with chips for weekly rank, win odds, projected seed and the money week distance.
- `lib/charts.js` — hand-written SVG/HTML chart builders (bump, scatter, radar, weekly bars, diverging bars, heat table). Marks carry `data-tip` for the shared tooltip in `app.js`. Deliberately no chart library.

### Power score

One formula for everyone: `WEIGHTS` in `lib/engine.js`, in Dan's priority order. Standing 40% (`standing` 0.31, place in the real standings: wins then points for; `winPct` 0.09), scoring 28% (`pfPerGame` 0.20, `allPlay` 0.04, `form` 0.04), schedule left 17% (`sos` 0.17), rest-of-season roster 15% (`rosProj` 0.13, `depth` 0.02). `PARTS` groups them; each team gets `t.parts` (standing, scoring, schedule, roster sub-scores) shown as the four bars on a ranking row, and `t.seed` (standings place). There is no admin page or published config: the page never passes weights, so every device computes the same ranks from the same snapshot (`computeLeague({ weights })` is only for scripts). Each metric is z-scored across the 12 teams; score = `50 + 22 * weighted z`, clamped 1–99. `sos` is schedule wins (`t.schedWins`): sum over the remaining regular-season games of P(win vs actual opponent) − P(win vs average opponent), using the same `projMean` and pooled SD as the playoff simulation, so the projection block runs before the power score. The engine also still returns `rosScore`, `sosScore`, `resultsScore`. Bye weeks (`byes` input from `/api/ros`) count everywhere: `weekProj(id, w)` is zero on a player's bye (and this week if ruled out); each team's `weekProj[w]` is its best lineup that week; `rosProj` is their regular-season average; `muWeek[w]` (week-specific strength) drives schedule wins and the simulation, so drawing a team in its bye-heavy week counts as easier. `effWeekly` (lineup display, position groups, Trade lab) is the per-game projection times health times the share of remaining regular-season weeks not lost to a bye. If `/api/ros` fails, ROS terms are dropped (schedule stays, using points per game) and the page shows a "results-only mode" notice. Rank history holds the ROS and schedule terms at today's value, so week-to-week movement comes from results only.

### Week in progress

After Thursday night the current week is partly played. An NFL team counts as played once any rostered player of theirs has a non-zero score in `matchups[upcoming]`. In `computeLeague`: `liveProj(id)` is actual points for played players, else `thisWeekProj`; each team gets `t.live = {banked, rest, left, played[]}` (locked starters' points, best lineup of not-yet-played players in the open slots, share of slots still open). `muWeek[upcoming]` becomes banked plus the blended rest, and `sdWeek[upcoming] = sd * sqrt(left)`, which drives the previews' win odds and the simulation (playoff and title odds). Previews carry `liveA/liveB`. `D.live = {week, teams}`. Season PF and records stay Sleeper's official numbers until the week is scored. The matchup breakdown tags played players FINAL and never suggests swapping them. `buildStories` adds a `dud` and a `star` story from the played games; the `editor` option (`EDITOR` in `app.js`, Dan) makes his own underperforming starter the dud and the lead. Hand-written headlines live in `PUNS` in `lib/stories.js`.

## Design system

Concept: a day game. A flat sky over a mowed football field, built from flat colour layers stacked on hard ledges: no blur, no glass, no soft shadows. Light only.

- Palette in `:root` of `styles.css`: `--grass #4CAF50`, `--grass-2 #8BC34A`, `--lime #CDDC39`, `--yellow #FFEB3B` (the first-down line: your team), `--amber #FFC107` (the goalposts: actions, the active tab, featured cards). Supporting: `--sky-1/2/3`, `--board #13301C` (scoreboards), `--turf #1B5E20` (end zone), white cards with `--tile`/`--tile-2` inner layers, `--ink`/`--ink-2`/`--ink-3` (all at least 4.5:1 on white and tile), `--good`/`--bad`/`--flag`, and matchup sides `--a`/`--a-ink` (blue, left team) vs `--b`/`--b-ink` (amber, right team).
- Text sitting directly on the grass must be `--ink` (5.2:1); the muted inks fail on green, so small text there goes on a white chip (`.sec-title`, `.day > h3`, filter pills).
- Type: Big Shoulders Display (numerals, team names, headings) + Albert Sans (body). Tabular numbers on.
- `.glass` is the flat card: white face plus `box-shadow: 0 var(--lift) 0 var(--ledge-c)`. `.glass.rim` = featured, on a gold ledge (top-3 ranks, trades, best trade idea, scoreboards). Your team gets a 4px yellow ring (`.mine .rank-card`, `.wire-team.mine`, `.mu.rim`), or the `--mine-bg` tint inside white panels. Hover lifts a card and deepens `--lift`. Buttons are pills on a 3px ledge that press down on `:active`. Radii step with hierarchy: 32/24/16px cards, pills for controls.
- The field: `main` is a one-column grid so each page's heading is row 1. `main::before` is absolutely placed from grid line 2 to the bottom and bleeds to the window edges (mowing stripes, a chalk yard line every two stripes); `main::after` is the chalk sideline (hidden on phones). Keep every view's heading as the first child of `#app` or the grass starts in the wrong place. The sky is `.sky` (fixed flat bands plus three CSS clouds, one on phones). The footer is the end zone (`.footer::before` with a white goal line).
- Scoreboards: the headline carousel and the game of the week are dark `--board` cards with white type and yellow accents; the game of the week's graphic is the playoff drive (`playoffDrive`/`paintDrive` in `app.js`): a mini field from 0% playoff odds to the end zone at 100%, one football per team on its current odds, and Today / A win / B win buttons that slide both balls to `playoffIfWin`/`playoffIfLoss` (transform only) with a chalk mark where they started and a sentence spelling out the swing.
- Signature element: each rank painted on the grass like a yard number (white, top three yellow) with a hard offset shadow, half under its card. Keep that the one bold move; keep everything else quiet.
- Charts: `TEAM_COLORS` in `lib/charts.js` is a 12-colour order checked with the dataviz palette validator on white (every adjacent pair clears colour-blind and normal-vision separation). Labels wear ink, never the series colour; dots get a white ring.
- Copy rules: sentence case, plain verbs, no ALL-CAPS eyebrow labels, no emoji, no "A · B · C" middle-dot strings. Exception by request: last place always gets the tier label "This Guy Stinks" (`tierFor` in `lib/engine.js`).
- Must stay usable at 390px wide; check the `@media (max-width: 760px)` block when adding layout.
- Motion (the "motion" section of `app.js` + the motion block in `styles.css`): tab changes use the View Transitions API (the header and `.tab-ink` show only their old picture so they stay solid, `page-title` morphs, and the page picture, sky and grass included, slides in by tab order via `data-dir`). Old and new page pictures cross-fade with `mix-blend-mode: plus-lighter` and identical keyframe stops so they always add up to opaque: Safari draws the old picture on top, and any mismatch washes the grass out mid-change. `.tab-ink` is the amber active-tab pill; `placeInk` re-measures on `load` and `document.fonts.ready` because a fast first render can measure the tabs before the stylesheet applies; `reveal()` uses one IntersectionObserver to rise cards in and count numbers up (`COUNT` selectors) as they scroll into view; bars grow, chart lines draw (`pathLength="1"`) and both stay paused until their card is revealed. Only transform/opacity are animated. All of it is skipped under `prefers-reduced-motion` (no view transition, no reveal classes, and the global rule kills CSS animation). The headline carousel auto-advances when the active dot's 7s fill animation ends, so it also stops under reduced motion. Keep `view-transition-name` values unique per page or the transition aborts. Phone smoothness rules: the carousel pauses rotation when under 60% visible (rotating changes its height on phones, and iPhone Safari has no scroll anchoring, so content below would jump); resize work only runs on real width changes (iPhone fires resize as its toolbar hides during every scroll); opening a ranking row pins its jersey number at its current pixel position instead of re-positioning it; count-ups lock each number's final width first so growing digits never nudge layout, and phones only count what's on the first screen; tooltips follow the mouse but are tap-to-show on touch and hide on scroll. Matchup cards expand to the full grid row on desktop with a FLIP glide (`toggleMatchup`). Phones and touch screens (`lite()`: max-width 760px or coarse pointer) get the light set only: tab pill slide, carousel (swipe, auto-advance, headline fade), one-time row rise, count-ups and expand. No view transitions, no scroll reveals, no bar/line animation, no hover lift. Nothing uses `backdrop-filter` or blur, so phones get the same surfaces as desktop. The carousel is square on desktop; on phones (<= 760px) it drops the square and `fit()` in `bindCarousel` sizes the track to the story on screen (re-run on slide change, resize and `document.fonts.ready`), so short stories leave no gap. Never pause the carousel on bare `:hover` or `:focus-within`: phones keep tapped elements in those states and the carousel would freeze. Test phone changes in WebKit (Playwright `devices['iPhone 13']`), not only Chrome emulation.

## Gotchas

- Sleeper roster `fpts` etc. are split into integer + `_decimal`/100.
- Sleeper team defenses use the team abbreviation as player ID (`"DET"`). Ranking sites spell some teams differently; `TEAM_FIX` in `sources.js` normalises (JAC→JAX, WSH→WAS…).
- Players the sources haven't listed yet (fresh signings) project 0. Patch them in `OVERRIDES` in `lib/overrides.js` (`{pos, wk}`); `app.js` applies it before `computeLeague`, only while the consensus has no `wk` for that player, and the footer lists active patches. Remove entries once the sources catch up.
- Name mismatches go in `NICKNAMES` (e.g. Bam Knight → Zonovan Knight, Cameron Skattebo → Cam Skattebo). Check `/api/ros` → `sources.*.matched` after changes; ~190 of 194 rostered players should have values.
- Scrapers may be blocked from Vercel IPs (browser-like User-Agent is set). A failed source degrades gracefully; don't make the whole endpoint fail on one source.
- Sleeper asks for `/players/nfl` at most once a day; only `api/ros.js` calls it, and the edge cache enforces that. Never call it from the browser.
- Sleeper is called only by `api/league.js` and `api/ros.js`, on the clock: once per morning, plus the Sunday late pull and the Monday final pull for the league. Dan does not want extra pulls: not on deploys, not for testing, not from new features. Keep reads going through `once()` with a clock key, never add browser calls to Sleeper, and ask Dan before adding any new Sleeper read or pull time. Testing uses the demo snapshot, fixtures and `?at=` (which fakes the page clock only; data keys follow the real clock).
- Ranking data belongs to FantasyPros, DraftSharks and LeagueLogs; this is a personal, non-commercial league site. Keep the attribution in the footer.
- The footer sponsor block is intentional: Dimassi's (struck through, contract expired) and the current sponsor TTP (Texas Truck Parts) with `assets/ttp-logo.png`. The source logo's "TT" letters were transparent knockouts; the PNG has them filled white so they show on the dark background. `bundle-preview.mjs` inlines the logo as a data URI.
- Anything tappable to expand uses the shared `XP` circle in `app.js` (`.xp` in CSS), which flips when its parent is open.
