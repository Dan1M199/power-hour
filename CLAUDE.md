# CLAUDE.md — The Power Hour

Context for Claude Code working in this repo. Read README.md for the user-facing overview.

## What this is

A shareable website for Dan's 12-team Sleeper fantasy league, **NFL Fantasy Championship** (league ID `1312001652454088704`, 2026 season). Leaguemates open it to see power rankings with explanations, a live waiver/trade feed, weekly matchup odds, and "nerd lab" stats. "The Power Hour" is also the name of Dan's league newsletter. Hosted on Vercel from GitHub; every push to the main branch deploys.

League facts the code relies on: half-PPR, 12 teams, starting slots QB, RB, RB, WR, WR, TE, FLEX, FLEX, K, DEF + 5 bench. Regular season ends week 14, playoffs start week 15, top 6 make it. Standings tiebreaker is points for. Waivers are rolling (no FAAB used in practice).

## Architecture

No framework, no build step, no npm dependencies. Plain ES modules served as static files.

- `index.html`, `styles.css`, `app.js` — the site. The browser never calls the Sleeper API: it loads `/api/league?d=KEY` and `/api/ros?d=KEY`, where KEY is the Central date rolling over at 6am (`morningKey()`), so each is fetched once per morning and shared from the CDN (and kept an hour by the browser, `max-age=3600`: a key's snapshot never changes). Load order: the `<head>` preloads both Latin font files, `<link rel="modulepreload">`s `app.js` and every `lib/` module the page imports (add a new front-end module there too, or it becomes a second round trip), and an inline `<script type="module" async data-early>` imports only `lib/newsclock.js` and starts both data requests while the rest of the code downloads (`window.__early`, skipped in the demo); `loadLive()` reuses them through `early()` when the URL still matches and sets `window.__early` itself first if they never started, so a request is never made twice.
- `api/league.js` — the morning Sleeper snapshot: state, league, users, rosters, matchups weeks 1–14, transactions weeks 1–current, plus `fetched`. It only answers the current key from `leagueKey()` (any other `?d=` gets a 307 to it) and keeps each snapshot in the store (`once('league', key)`, 3 days), so a deploy (Vercel empties the CDN) never re-reads Sleeper. `X-Snapshot` says `store` or `live`. `max-age=3600, s-maxage=86400`; errors are `no-store`. Also exports `snapshot()` for scripts. Hash routing: `#live` (only during a live week), `#rankings`, `#wire`, `#matchups`, `#trades`, `#lab`.
- `api/ros.js` — Vercel serverless function (Node 18+, global `fetch`). Scrapes the three ROS sources, fetches Sleeper's `/players/nfl` (~5 MB), matches players to Sleeper IDs, returns `{ updated, sources, weights, players: {id: {n,p,t,i,a}}, values: {id: {v, r, spread, pos, wk, fl, cl, ir, sos, g, rk, prk, wkEst?}}, byes: {TEAM: week}, weekly: {week, sources, proj: {id: [pts, fp, sl]}} }`. Bye weeks come from FantasyPros (`player_bye_week` on every ecrData row). Only the current `morningKey()` is served (others redirect). Sleeper's player map is slimmed to fantasy positions and stored on its own (`once('players', key)`), so it's read at most once per morning; the built body is stored for 3 days, or 1h when a ranking source failed (the retry re-scrapes the rankings and reuses the stored players). Edge-cached 24h (`s-maxage=86400`) and an hour in the browser (`max-age=3600`); if a source failed, 1h at the edge and not at all in the browser. No cron; the only database is the fan-picks store behind `api/votes.js`.
- `lib/weekly.js` — this week's player projections for the matchups, pure: the plain average of FantasyPros' API (`/public/v2/json/nfl/{season}/projections`, `points_half`, env `FANTASYPROS_API_KEY`) and Sleeper's projections endpoint (`api.sleeper.app/projections/nfl/{season}/{week}`, `pts_half_ppr`), whichever has the player. `api/ros.js` fetches both for `nflWeek(morningKey)` (weeks turn over Tuesday; `SEASON_TUESDAY` needs updating each season) and stores each on its own (`once('fpproj'|'slproj', key)`), so it's one Sleeper call and about 23 FantasyPros calls per morning. FantasyPros' free tier returns 10 players a call and answers bursts with 429, so `fpIdsToAsk` picks the likely starters from its ROS ranking (`FP_DEPTH`, by `fpid` from ecrData), one call every `FP_GAP_MS`, with retries. Without the API key it runs on Sleeper alone (no hourly retry). The engine uses `weekly` only when `weekly.week` is the upcoming week: `thisWeekProj` reads it (DraftSharks' ROS `wk` for a player neither has), `muWeek[upcoming]` and the live rest are the projection itself (no scale or points-per-game blend), and each preview's `projA/projB` is `t.setProj`, the set lineup's projection (the best lineup if none is set), the same total `breakdown()` adds up. Floors and ceilings are DraftSharks' scaled by this week's projection over `wk`. `meta.hasWeekly` switches the Games copy.
- `lib/newsclock.js` — the shared clock (page and API): `TZ`, `NEWS_CLOCK` (hold, late pull, night edition, game window), `morningKey`, `leagueKey`, `isOnHold`, `isNightDesk`, `inGameWindow`. Export names must not clash with names in `app.js`: the preview bundler flattens modules into one scope and can't follow `import { a as b }`.
- `lib/snapstore.js` — `once(name, key, produce)`: each snapshot kept gzipped in the Upstash store (same env vars as the fan picks) under its clock key, with a lock so simultaneous first visitors share one pull. Without the env vars it falls back to pulling on each CDN miss. `scripts/test-snapshots.mjs` counts Sleeper calls.
- `lib/sources.js` — regex-only parsers (must run in Node without a DOM):
  - FantasyPros: `var ecrData = {...};` embedded in the page HTML (~400 players incl. K/DST).
  - DraftSharks: the page only server-renders 25 rows; the full list is `GET /ros-rankings/load-rows?offset=0&limit=600&...` (HTML `<tr class="player-row">` fragments, includes IDP, re-ranked within offense). Also provides weekly proj pts, floor, ceiling, injury risk %, SOS, projected games.
  - LeagueLogs: server-rendered `<table>`, 200 players incl. DST, no K. Its order nearly mirrors FantasyPros ECR, so it is weighted 0.5.
- `lib/consensus.js` — `normName` + `NICKNAMES` map, `buildIndex(sleeperPlayers)`, `matchRow`, `buildConsensus`. Rank → value is `100 * exp(-0.0115 * (rank-1))`, weighted average across sources (`SOURCE_WEIGHTS`). Missing weekly projections are filled by a per-position linear fit of DraftSharks pts vs value, falling back to `DEFAULT_FIT` if DraftSharks is down.
- `lib/engine.js` — `computeLeague(input)`: pure, no DOM, runs in browser and Node. Produces teams (sorted by power rank), weekly results, all-play, luck, efficiency, ROS best lineup (greedy fixed-then-flex), position-group ranks (`groupScores`, quality over quantity: each starter's weekly projection minus the league baseline at his position, `meta.posBase`, the Nth-best rostered player with N = teams × dedicated slots, so WR24, RB24, QB12, TE12; dedicated slots weigh `GROUP_W.fixed` 1.25 and can go negative, flex use weighs 0.5 then 0.25 and never below zero, so a pile of middling receivers can't outrank a better group one player shorter; the Trade lab scores groups the same way, and tooltips read "+x pts/wk over the WR24 line" via `groupSaid` in `app.js`), power score + rank history, Monte Carlo playoff odds and championship odds (10k sims, seeded; the playoff bracket is simulated on Sleeper's fixed 4/6/8-team bracket, giving `champPct`/`finalPct`; `simulate` runs on team indexes and typed arrays but draws the same random numbers in the same order as the plain version it replaced, and `scripts/test-engine.mjs` checks a fingerprint of the fixture's odds, so a change to it that shifts any probability fails the test), matchup previews, explanations (`explain`), tiers (`tierFor`), transaction feed with ROS value deltas (trades priced over replacement: each net extra player received costs `meta.replacement`, the mean value of the top 3 free agents, so consolidation trades are not penalised; waiver moves stay raw), best available free agents, "divisive" players.
- `lib/stories.js` — the newsroom, pure like the engine. `buildStories(D, {now, dateKey})` scores candidate stories (fresh trades and wire moves, unbeaten/winless/streaks, last week's upsets/blowouts/nail-biters, rank moves, luck, game of the week) and returns `{lead, more}`; a date-seeded jitter rotates near-ties daily. `keyMatchup(D)` picks the game of the week by 0.55 × stakes + 0.45 × closeness, where stakes is the combined playoff-odds swing (`playoffIfWin − playoffIfLoss` from the simulation). `matchupQuips(D)` gives one data-driven one-liner per matchup, no repeated joke within a week.
- `api/votes.js` — fan picks. GET `?week=&voter=` returns `{week, open, counts: {"3-8": {"3": n}}, mine}`; POST `{week, pair, pick, voter}` records a vote (re-voting replaces the device's pick). Storage is Upstash Redis over its REST pipeline API with plain fetch (env `KV_REST_API_URL`/`KV_REST_API_TOKEN` or `UPSTASH_REDIS_REST_*`); without them GET returns `{enabled: false}` (200, no console noise), POST returns 503, and the UI hides voting. Server validates against the cached `/api/league` snapshot on its own host (current week, real pair, pick in pair), never Sleeper directly, and closes voting from Thursday 7:15pm Central through Monday or once the snapshot shows points. `VOTES_NOW` env overrides the clock in tests. Soft cap of 3 voters per hashed IP per matchup. Keys `ph:votes:{week}:{pair}` (hash voter→pick) and `ph:net:{week}:{pair}:{iphash}` (set), 120-day TTL. The client keeps its voter id in `localStorage` `ph-voter` and hides the split until you've voted.
- `api/talk.js` — the league desk, one discussion thread per week beside the headlines (a hash of comment id → `{id, uid, text, ref, ts, edited?}`, 300-day TTL, refreshed on each post). Everything lives in the store, never in code or the CDN, so deploys and headline edits can't touch it; a comment keeps its own copy of its headline's title, so a rewritten or retired headline only greys out its chip. Keys come from `threadKey(week)`: the 2026 threads stay where they were first stored, `ph:talk:{week}`, and later seasons (`seasonOf`: September into the next summer) get `ph:talk:{season}:{week}`. Never rename these keys without moving the data. Anyone reads (`GET ?week=`, `no-store`); posting needs a session. Identity: Sleeper has no sign-in for outside sites, so each manager gets a personal link from Dan, `/#join=<token>` (after the `#`, so it never reaches logs or the CDN). `POST {action: 'claim', token}` checks the token's hash (`ph:talk:tok:{sha}` → Sleeper user id) and sets an HttpOnly `ph_who` session cookie (`ph:talk:sess:{sha}` → `uid:generation`). `TALK_ADMIN_KEY` (env, 16+ chars) claims as Dan (`ADMIN`, his user id) to bootstrap. `invite` (Dan only) makes a new link for a `MEMBERS` or `GUESTS` id (`DESK_PEOPLE` in `lib/members.js`; a guest such as Dan's cousin Saad, "Ex Player Saad", is outside the league: full display name, an `icon` picture such as `assets/heads/helmet.svg`, a "Guest" tag in place of a team, and nothing else on the site reads `GUESTS`), deletes the old token and bumps that manager's generation, which signs out every device on the old link. The server always files a comment under the session's user id; the page shows the `MEMBERS` first name and the team's current name. `post` (1–500 chars, cleaned, one per `GAP_S` per manager, `ref` = `{key, title}` of a headline or null), `edit` (author only, within `EDIT_MS`, one minute), `delete` (Dan only), `signout`. Never touches Sleeper. `scripts/test-talk.mjs` covers it. In `app.js` (the "league desk" section): `talkSlot()` sits in the `.hero` of the rankings and Live pages (not in the demo or the preview); with the store on, `.hero.with-talk` puts the carousel across both rows on the left (`align-self: start` keeps it square) and the desk under the page head on the right, scrolling inside itself (`.talk-in` is absolutely placed); at 980px and below it drops under the carousel. Comments sit in a tray as white bubbles, yours on `--mine-bg`. The header is a title row (Invite links for Dan) over a meta bar (week picker, count, "Posting as" with Sign out). Minor actions (Sign out, Edit with its seconds, Delete) are small tray pills (`.tc-pill`, `.tc-act`), never underlined links; on a mouse, Dan's Delete sits in the corner of the comment under the pointer. Untagged, the composer offers a dashed "+ Tag the headline on screen" pill; tagged, a solid chip. The first keystroke tags the headline on screen (`currentHeadline()` from `carouselNow`, the carousel's index and `go`, set in `bindCarousel`; `carouselStories` from `leadStory`; keys `w{week}:{type}` from `storyKeys`), and a comment's `On:` chip turns the carousel back to it. The thread on screen is this week's (`talkWeek()`, from the raw snapshot's last scored week, so it turns over Tuesday morning and not when the Monday final call counts the week early); a week picker reads back through earlier threads (`TALK.view`), read-only. Refreshes every 25 s while visible, repainting only the list so a draft survives. `main()` takes `#join=` off the address bar before routing and `claimTalk()` trades it for the session (and picks their team if none is picked).
- `lib/matchup.js` — `breakdown(D, preview)`: this week's lineups slot by slot (the starters set in Sleeper, from `preview.startersA/B`; best projected lineup when a team hasn't set one), position-group edges, and up to 6 prioritised "things to watch" (`urgent` when priority >= 90: a sure zero, an empty slot, a bench swap; `watchItem` in `app.js` bolds their first sentence on a flag pip and bolds player names in every line) (starters ruled out or on a bye, legal lineup swaps found by greedy slot-eligible bench swaps, doubtful/questionable starters, biggest edges, close or lopsided totals, the widest floor-ceiling swing player, QB stacks, shared NFL offenses, hot or cold form). The engine's `thisWeekProj` is zero for players ruled out or on a bye (`byes` input), which also feeds this week's win odds. `helpers.player(id)` returns name, NFL team, status, bye, proj, floor, ceiling.
- `lib/trades.js` — `tradeIdeas(D, rid)`: brute-force search of every 1-for-1, 2-for-1 and 1-for-2 swap with each other team (skill positions, value >= 8; about 25ms: per-player lookups are memoized, and the partner's lineup is only worked out once the requester's has cleared its bar). Kept only if the requester's best ROS lineup gains >= 0.3 pts/wk, the partner's doesn't drop and gains >= 0.1 unless they win the value side by >= 3, and value (over replacement, same rule as the trade ledger) is within max(6, 15% of the deal). Roster fallout is modelled: an extra player received forces the lowest-value skill player to be cut; a freed spot adds the best free agent. Max 2 ideas per partner and per incoming headliner. Explanations come from position-group ranks before and after. No AI model involved; it is a deterministic search.
- `lib/members.js` — `MEMBERS`: Sleeper user_id → `{first, photo}` for the league managers, with headshots in `assets/heads/<photo>.jpg` (320px square JPEGs cropped from the originals, about 25 KB each). `photoUrl()` reads `window.__HEADS__` first, which `bundle-preview.mjs` fills with data URIs. A picture that fails to load turns into its initials (`data-initials`) through one capturing `error` listener on the document (`initAvatarFallback`), so renders never attach their own. In `app.js`, `avatar(t)` stays the Sleeper team picture (Dan wants team pictures in the ranking rows, the wire and the matchup cards); `headshot(t, cls)` is the manager photo (falls back to `avatar`). Headshots appear in the headline photos (`leadFaces`, with a `STAMPS` label per story type), the manager card at the top of an opened ranking row (`managerCard`, plus `superlatives` badges), the game of the week poster (`faceoff`) and its playoff-drive legend, the busiest manager in the wire stat strip, who shook on each trade card (`dealFaces`), the partner on your best Trade Lab idea (`.pitch`), photo marks in the scatter chart and on your own line in the bump chart (`img`, `faceDot` in charts.js), your face next to the team picker (`paintMe`), and the editor line in the footer. Last place (the "This Guy Stinks" tier) gets the `.drained` grayscale. Keep them sprinkled: one or two personal moments per page, not every list. A new manager needs an entry in `MEMBERS` and a cropped photo.
- `lib/bullseye.js` — money week side pots. `bullseye(D, {week, target})`: during the week, every team's projection (banked plus the rest, same as the previews) sorted by distance from the target, plus `pWin` from 20k seeded draws of who lands closest; the week after, the final scores and the winner; `soon` before; null otherwise. `MONEY_WEEK` in `app.js` (week, target, prize, usual, title, honoree, flyer) drives a lead headline (`moneyStory`, always first while it runs) and a distance chip on each matchup card (`bullTag`). The bullseye board that used to sit on the matchups page (target chart, ticket, flyer, table) was removed at Dan's request; `MONEY_WEEK.flyer` and `assets/money-week-flyer.jpg` are unused now. Safari won't fetch a `preload="none"` video on `play()` alone, hence `load()` first; a `play()` cut short by `pause()` (`AbortError`) doesn't count as refused.
- `lib/nightdesk.js` — the night edition, pure. `nightBoard(D)` splits this week's games, using the breakdown's set lineups, into locked (the trailing side's Monday players can't cover the gap even at their DraftSharks ceilings, or nobody is left, or the leader is above 98.5%) and Monday-decides. A finished game (nobody left on either side) is always locked, even dead level: a tied final once went to the Monday branch, which reads a Monday star who doesn't exist, and took the whole page down. Ties get their own headline. `nightEdition(D, {dateKey, editor, people})` writes three aggressive headlines (the tightest Monday decider, the biggest locked game, then the next best; the editor's own live game is always in), with first names from `people` and decks carrying scores, the Monday players and projections, win odds, the new records or the playoff-odds swing. It returns null unless at most four NFL teams are still to play, so a mid-Sunday snapshot never gets a night edition. Money week still leads, so the carousel shows four slides that night.
- Live-week mode (`DATA.liveMode`): during the game window (`gameWindow()`, Thursday 7:15pm to Tuesday 6am Central) or whenever this week has points (`DATA.live`), as long as the week is unscored, the Live tab (`viewLive`, `#live`, hidden otherwise) is the front page and the brand link. The power rankings tab stays reachable but shows "On hold" and a notice that they update Tuesday morning, with no carousel. Phones show short tab labels (`.tl`/`.ts` spans: Live, Power, Wire, Games, Trades, Lab). The bare URL opens Live; an explicit hash still wins. The weekly list and the standings sit side by side from 1100px (`.live-grid`, standings sticky, PF column moved into the After tooltip), stacked below. Above them, `yourWeek()` is the desk's note to whoever picked a team (headshot, rotating line by situation: won/locked, comfortable, losing, close and ahead gets hype, close and behind gets a reality check; extra jab for last place), with chips for weekly rank, win odds, projected seed and the money week distance.
- `lib/labmodels.js` — two Nerd lab models, pure and deterministic, tested by `scripts/test-lab.mjs`. `whatItTakes(D, {sims, seed})`: plays out the rest of the regular season (16k seeded seasons, the same model as the playoff odds: `muWeek`/`sdWeek`, standings by wins then points for) and groups the seasons by how many remaining games each team won, giving P(playoffs | win k more) per team, the most likely win total (`likely`), the fewest wins for 90% (`magic`) and 50% (`coin`); cells backed by too few seasons come back `odds: null`; its overall odds land within a point or two of the engine's. `trueTalent(D)`: empirical-Bayes shrinkage of each team's points per game toward its roster projection (`rosProj` put on the league's scoring scale): sigma is the pooled within-team weekly SD, tau comes from the method of moments, floored at 6 pts/week (the projections already lean on this season's results, so the raw estimate lands near zero), and each team gets a best guess from here with an 80% range, the shift from its scoring so far, the weight its own scores carry, and a verdict (`hot` ≤ -4, `under` ≥ +4, else `real`). In `app.js`, `witPanel()` renders "What it takes" (a heat table of conditional odds, the ring on the likely win total, a "For 90%" chip, a `.lab-lede` line for the picked team; on phones it opens scrolled to that team's likely column) and `talentPanel()` renders "Fluke or for real?" (an HTML lane per team: ring = scoring so far, dot = best guess, glossy pill = 80% range in the verdict's colour, ink arrow between them; on phones the lane drops under the name). Both are memoised on `DATA` (`_wit`, `_talent`).
- `lib/charts.js` — hand-written SVG/HTML chart builders (bump, scatter, radar, weekly bars, diverging bars, heat table). Marks carry `data-tip` for the shared tooltip in `app.js`. Deliberately no chart library. Cartoon glass, like the cards: shared `dot` (ink ring plus glint), `bar` (ledge, ink edge, gloss capped at 12px) and `plate` (a tray behind the plot with chalk gridlines; `light` for a white plate inside a tray) helpers; bump lines are three paths (ink `case`, colour, `shine`); the scatter tints its four quadrants (`.q-tl` … `.q-br`); the radar is a white dartboard on a ledge (`.radar-plate`, `.radar-band`). With a `focus` team, the other teams' lines and dots dim to 38% (scatter faces 70%) with their casing hidden, but their labels stay at `--ink-3` (never faded). The manager card's stat tiles are toned by league rank (`leagueTone` in `app.js`: top third `.good`, bottom third `.bad`, moves neutral). The Nerd lab's playoff column is a filled pill (`.pbar`, `--v`). Heat tables run sky blue (good end) to amber (bad end), fading to white in the middle (colour-blind safe, no green-red), with a sticky team column; `heatTable({ mine })` and a diverging-bar row's `mine: true` mark your team (`--mine-bg`).

### Power score

One formula for everyone: `WEIGHTS` in `lib/engine.js`, in Dan's priority order. Standing 40% (`standing` 0.31, place in the real standings: wins then points for; `winPct` 0.09), scoring 28% (`pfPerGame` 0.20, `allPlay` 0.04, `form` 0.04), schedule left 17% (`sos` 0.17), rest-of-season roster 15% (`rosProj` 0.13, `depth` 0.02). `PARTS` groups them; each team gets `t.parts` (standing, scoring, schedule, roster sub-scores) shown as the four bars on a ranking row, and `t.seed` (standings place). There is no admin page or published config: the page never passes weights, so every device computes the same ranks from the same snapshot (`computeLeague({ weights })` is only for scripts). Each metric is z-scored across the 12 teams; score = `50 + 22 * weighted z`, clamped 1–99. `sos` is schedule wins (`t.schedWins`): sum over the remaining regular-season games of P(win vs actual opponent) − P(win vs average opponent), using the same `projMean` and pooled SD as the playoff simulation, so the projection block runs before the power score. The engine also still returns `rosScore`, `sosScore`, `resultsScore`. Bye weeks (`byes` input from `/api/ros`) count everywhere: `weekProj(id, w)` is zero on a player's bye (and this week if ruled out); each team's `weekProj[w]` is its best lineup that week; `rosProj` is their regular-season average; `muWeek[w]` (week-specific strength) drives schedule wins and the simulation, so drawing a team in its bye-heavy week counts as easier. `effWeekly` (lineup display, position groups, Trade lab) is the per-game projection times health times the share of remaining regular-season weeks not lost to a bye. If `/api/ros` fails, ROS terms are dropped (schedule stays, using points per game) and the page shows a "results-only mode" notice. Rank history holds the ROS and schedule terms at today's value, so week-to-week movement comes from results only.

### Week in progress

After Thursday night the current week is partly played. An NFL team counts as played once any rostered player of theirs has a non-zero score in `matchups[upcoming]`. In `computeLeague`: `liveProj(id)` is actual points for played players, else `thisWeekProj`; each team gets `t.live = {banked, rest, left, played[]}` (locked starters' points, best lineup of not-yet-played players in the open slots, share of slots still open). `muWeek[upcoming]` becomes banked plus the blended rest, and `sdWeek[upcoming] = sd * sqrt(left)`, which drives the previews' win odds and the simulation (playoff and title odds). Previews carry `liveA/liveB`. `D.live = {week, teams}`. Season PF and records stay Sleeper's official numbers until the week is scored. The matchup breakdown tags played players FINAL and never suggests swapping them. `buildStories` adds a `dud` and a `star` story from the played games; the `editor` option (`EDITOR` in `app.js`, Dan) makes his own underperforming starter the dud and the lead. Hand-written headlines live in `PUNS` in `lib/stories.js`.

## Design system

## Gotchas

- Sleeper roster `fpts` etc. are split into integer + `_decimal`/100.
- Sleeper team defenses use the team abbreviation as player ID (`"DET"`). Ranking sites spell some teams differently; `TEAM_FIX` in `sources.js` normalises (JAC→JAX, WSH→WAS…).
- Players the sources haven't listed yet (fresh signings) project 0. Patch them in `OVERRIDES` in `lib/overrides.js` (`{pos, wk}`); `app.js` applies it before `computeLeague`, only while the consensus has no `wk` for that player, and the footer lists active patches. Remove entries once the sources catch up.
- Name mismatches go in `NICKNAMES` (e.g. Bam Knight → Zonovan Knight, Cameron Skattebo → Cam Skattebo). Check `/api/ros` → `sources.*.matched` after changes; ~190 of 194 rostered players should have values.
- Scrapers may be blocked from Vercel IPs (browser-like User-Agent is set). A failed source degrades gracefully; don't make the whole endpoint fail on one source.
- Sleeper asks for `/players/nfl` at most once a day; only `api/ros.js` calls it, and the edge cache enforces that. Never call it from the browser.
- Sleeper is called only by `api/league.js` and `api/ros.js`, on the clock: once per morning (for ros: the player map and, approved by Dan, this week's projections), plus the Sunday late pull and the Monday final pull for the league. Dan does not want extra pulls: not on deploys, not for testing, not from new features. Keep reads going through `once()` with a clock key, never add browser calls to Sleeper, and ask Dan before adding any new Sleeper read or pull time. Testing uses the demo snapshot, fixtures and `?at=` (which fakes the page clock only; data keys follow the real clock).
- Ranking data belongs to FantasyPros, DraftSharks and LeagueLogs; this is a personal, non-commercial league site. Keep the attribution in the footer.
- The footer sponsor block is intentional: Dimassi's (struck through, contract expired) and the current sponsor TTP (Texas Truck Parts) with `assets/ttp-logo.webp` (144px, 5 KB, lazy and low priority; re-encoded in headless Chromium from the master `assets/ttp-logo.png`, 84 KB, which the page never loads). The source logo's "TT" letters were transparent knockouts; the PNG has them filled white so they show on the dark background. `bundle-preview.mjs` inlines the logo as a data URI.
- Anything tappable to expand uses the shared `XP` circle in `app.js` (`.xp` in CSS), which flips when its parent is open. Ranking rows say it louder: a drawer pull along the bottom of each card (`.pull` inside `.rank-btn`, "Scouting report", "Hide report" when open). Until a device has opened any team (`localStorage` `ph-opened-rank`), the #1 row is `.nudge`: an amber pull reading "Tap for the scouting report" with the chevron bobbing three times.
